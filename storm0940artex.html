Tracking offensive AI tooling in the wild

A living tracker of agentic offensive-security frameworks — ARTEX, CyberStrikeAI, PentAGI, Cairn and HexStrike — as they are used in real intrusions, with attack paths, TTPs and IOCs per tool. The ConnectWise breach review this page started as is kept below as a case file.

The shift HIGH

Agentic offensive frameworks — built as legitimate pentest tools — are now doing live intrusions for criminals and state-aligned actors alike, at machine speed and for dollars per target.

Confirmed in vendor incident response (GTIG, Microsoft, Kaspersky, TrendAI), government advisory (CERT-In CIAD-2026-0058) and operator infrastructure exposed in the open.

Attribution MEDIUM

Five frameworks, many operators. The tool name is the weakest link: shared tooling does not mean a shared actor.

Operators stack frameworks on the same hosts. Hunt the operator’s behaviour — infrastructure, targets, model, post-exploitation tooling — not one tool’s fingerprint.

ARTEX

Open-source, LLM-driven autonomous penetration-testing framework · developer known as Autumn-27 · published on GitHub as Autumn-27/ARTEX on 26 July 2026 under AGPL-3.0 · Go backend, Next.js web console, PostgreSQL · upstream repository taken down / made closed-source by the developer in October 2026 after abuse reports; forks and copies continue to circulate

A multi-agent framework that autonomously runs a penetration test from reconnaissance through exploitation, privilege escalation and data collection, with little human input: it builds an asset graph of the target and an exploration graph of what has been tested, discovers exposed services, probes for vulnerabilities, generates and refines attack scripts, exploits them, and records findings and credentials. Model-agnostic — reported use of DeepSeek, Kimi, GLM and Grok via resellers and shims. Default console port 8787.

Attack path — new 9 November finding

Single source: H3NRY B41T on Medium, 9 Nov 2026, based on Hunt.io AttackCapture data. An open directory (1,235 files, 309 MB, 566 flagged malicious) on a staging server exposed an ARTEX-assisted campaign running 2–6 Nov against enterprise infrastructure in Japan (primary), Taiwan, Korea and the US. Status: reported — no vendor or government corroboration as of 9 Nov, and no actor name or state link is asserted.

CyberStrikeAI

Open-source, Go-based, AI-native autonomous penetration-testing platform · developer alias Ed1s0nZ · first published on GitHub as Ed1s0nZ/CyberStrikeAI on 8 November 2025, Apache-2.0 · acquired by ThreatBook on 30 September 2026, which says it will keep the open-source edition available and launch an Enterprise Edition

PentAGI

Self-hosted, fully autonomous multi-agent penetration-testing platform · developed by VXControl L.L.C-FZ, Dubai Meydan Free Zone · GitHub repository vxcontrol/pentagi, MIT licence · repository created 6 January 2025, first public alpha v0.1.0 on 7 January 2025 · paid Enterprise Edition exists alongside the free Community Edition

The operator describes a target and a goal in plain language; a primary agent delegates to specialised agents (research, coding, installation, pentesting, adviser / reflector roles) which split the work into ‘flows’, sub-tasks and actions, run 20+ professional tools — nmap, Metasploit, sqlmap and other Kali Linux tools — inside isolated Docker sandboxes, use a built-in browser and search engines (Tavily, Firecrawl, Perplexity, DuckDuckGo, Google, Sploitus, SearXNG, Traversaal) for fresh intelligence, store results in PostgreSQL + pgvector (optional Neo4j / Graphiti knowledge graph), and produce a vulnerability report (web, Markdown or PDF). It supports 10+ LLM providers (OpenAI, Anthropic, Gemini, AWS Bedrock, Ollama / local models and other OpenAI-compatible endpoints) via REST / GraphQL APIs. It is explicitly not a CALDERA-style breach-and-attack-simulation product with predefined campaigns; the agents decide the next step. Use is restricted by its EULA to systems the operator owns or is authorised to test.

This entry covers oritera/Cairn, the open-source AI agent harness abused in live intrusions. Conflating the two would invert the entry.

A general-purpose problem-solving engine. The operator supplies an origin (starting point) and a goal; Cairn searches for a path through an unknown state space. Coding-agent workers (Claude Code, Codex and Pi CLIs) run observe-orient-decide-act loops and coordinate only through a shared ‘blackboard’ — a fact / intent / hint graph in which facts are confirmed findings, intents are next steps, and hints are human input. It defines no fixed roles or workflows. A dispatcher assigns tasks to workers (often in disposable Kali containers); a web console (default port 8000, served by uvicorn) shows projects, graphs and findings. Critically for defenders, Cairn ships with no authentication by default on that console — anyone who finds it can view projects, secrets and findings, and start, stop or redirect work. Built for, and first validated on, autonomous penetration testing: it solved 54/54 problems in the 2nd Tencent Cloud Hackathon AI penetration-testing challenge (610 teams, 1,345 participants), the only team to do so, finishing 3rd overall — per the project’s own README. The README states it is intended for use only where the operator has explicit authorisation.

Attack path

No source describes one canonical end-to-end path for all Cairn use — the path varies by campaign, and the composite below is assembled from the separate cases; gaps are marked.

  • Target selection / feeder. Traffic-ranked e-commerce / payment target lists, Playwright browser checks that orders can be placed (NorForge AIA0001); Strix deep-mode vulnerability scanning feeding targets to Cairn (Gambit).
  • Recon / probing. Agents iteratively probe public web apps — SQL injection, file upload, deserialisation, SSTI, SSRF, authentication bypass, directory enumeration — adapting after each error (NorForge; Sophos).
  • Exploitation / initial access. Unauthenticated RCE via web flaws and deployment of an uploader / web shell (confirmed at one commercial site by NorForge; skimmers on 19 sites in Gambit); unauthenticated Spring Batch job endpoint — Nashorn code execution (ReliaQuest); or valid / default credentials, e.g. admin/admin on a WSO2 API Manager console (VULONE, CDAC).
  • Post-exploitation. Credential discovery in configuration files and plaintext database credentials, API tokens and source code (VULONE; ReliaQuest); privilege escalation via xp_cmdshell — PrintSpoofer / GodPotato — SYSTEM (ReliaQuest; Sophos pattern 1), token impersonation and LSASS access (Sophos, reported).
  • Persistence. Web / uploader shells left for later return, backdoor admin accounts (ReliaQuest — one left in place), installed SSH keys and Poseidon implant in the panel-hijack cases (NorForge).
  • Collection / exfiltration. Payment-card records (Gambit, 600,000+), credentials / API keys and source code (VULONE), chunked 1,800-byte output retrieval via error messages (ReliaQuest), HTTP PUT /ev/ to operator listeners (VULONE).
  • Monetisation. Carding / skimmers (Gambit), card / crypto theft goals (AIA0002), persistent access ‘for later monetization’ (AIA0001).

Gaps: exfiltration volumes are largely unconfirmed (Reuters could not ascertain data extraction in the 100+ company case; VULONE found no bulk card theft in its artefacts); the Crafty Falcon payment-API abuse path is not attributed to Cairn specifically; and whether any given step was agent- vs human-driven is assessed, not proven, in the ReliaQuest and Sophos cases.

HexStrike AI

Open-source MCP-based offensive-security framework · author / developer Muhammad Osama (GitHub handle 0x4m4 / m0x4m4) · owned and developed by OTT Cybersecurity LLC, per the project README · repository github.com/0x4m4/hexstrike-ai · licence MIT · first published approximately August 2025 (Check Point’s 2 September 2025 blog calls it ‘newly released’; one chronology dates release to ~1 August 2025; some secondary sources say July 2025 — treat July–August 2025 as the window, August 2025 as the best-supported single date)

An MCP (Model Context Protocol) server — built on FastMCP — that lets LLM agents (Claude, GPT, Copilot, Cursor, VS Code Copilot, Roo Code, Claude Desktop) autonomously run 150+ professional security tools for penetration testing, vulnerability discovery, bug-bounty automation and security research. It has a multi-agent architecture with 12+ specialised agents (BugBounty, CTF Solver, CVE Intelligence, Exploit Generator, among others) and an abstraction / orchestration layer that translates vague operator commands (e.g. ‘exploit NetScaler’) into sequenced tool calls. Tool categories per the README: network reconnaissance (25+, incl. Nmap, Masscan, Amass, Subfinder), web application testing (40+, incl. Nuclei with 4,000+ templates, SQLMap, Gobuster, Nikto, WPScan), authentication / password (12+, incl. Hydra, Hashcat, John the Ripper), binary analysis / reverse engineering (25+, incl. Ghidra, Radare2), cloud security (20+), CTF and OSINT tools, plus a headless-Chrome browser agent. It includes retry / recovery logic so failed exploit attempts are automatically retried with variations.

Attack path

As described by Check Point (2 Sep 2025): operator gives a high-level intent (‘exploit NetScaler’) — the abstraction / orchestration layer translates it into precise sequenced steps — reconnaissance (Nmap scanning and other discovery tools) — vulnerability identification / exploit crafting, with parallel scanning of thousands of IPs — exploitation (unauthenticated RCE in the NetScaler case) — persistence via webshell deployment — data exfiltration. Check Point states the agents ‘perform specific actions; scanning, exploiting, deploying persistence, exfiltrating data.’ In the BOSSAI campaign (Acronis, 4 Nov 2026), where HexStrike AI was one of three remaining MCP servers in the mesh, the observed path was: asset discovery (FOFA, Shodan) — subdomain enumeration — concurrent scanning (nmap, nikto, ffuf, gobuster, dirsearch, cracked Acunetix) — vulnerability report assembled by one agent — attack-path report by another — exploitation by a third agent (SQL injection via sqlmap, default credentials) — data collection / exfiltration.

Gaps: no source publishes a HexStrike-specific lateral-movement or privilege-escalation step; webshell persistence and exfiltration in the NetScaler case rest on underground-forum actor claims relayed by Check Point, not independent observation; in BOSSAI, HexStrike’s contribution to any single victim step is not isolated from the Kali MCP server, sqlmap, Metasploit and other tools in the same mesh.

The tool is itself vulnerable

CVE-2025-35028 is a critical (CVSS 9.1) unauthenticated OS command-injection flaw in the HexStrike AI MCP Server (EnhancedCommandExecutor, semicolon-prefixed argument, typically running as root; Check Point advisory CPAI-2025-12521, published 2 Mar 2026). Secondary hardening guides as of Feb 2026 reported no fix confirmed. An exposed or compromised HexStrike instance inside a bank’s red-team / test environment would be a ready-made intrusion platform — patch or isolate any instance you run, and hunt for it on your own estate.

No HexStrike-specific exposure count, hash, domain or console fingerprint exists in the sources found. The BOSSAI IOC total is inconsistently reported (29 per Threadlinqs vs 18 network indicators per another summary). What the report does not contain

Each absence matters as much as the indicators that are there.

A service principal adding a credential to a different application. This is how the actor built access that disabling the ConnectWise app does not remove.

Operators stack frameworks

Censys (5 Nov 2026) found CyberStrikeAI co-located with ARTEX on 70 hosts, plus PentAGI, HexStrike AI and RedAmon on ARTEX hosts; one host (1.14.104.208) ran ARTEX and PentAGI alongside a Cobalt Strike teamserver (port 50050) and an Adaptix C2 listener (4321). Co-location proves operators stack frameworks, not that one actor runs both or that every co-located host is malicious — Censys and AhnLab both caution that exposed-tool presence alone does not establish malicious use. For detection, the stack is the signal: one host running two agent frameworks plus conventional C2 is a far stronger hunting lead than any single console fingerprint.

Static IOCs will not cover much of this activity — GTIG: much of it uses valid identities and supported functionality. Hunt the markers above in Entra/Graph, AWS/Azure control-plane, AD, web and MySQL logs, not just the next IP.

The tool is not the actor

ARTEX is public, widely forked, and its console is not a campaign selector.

ARTEX is an AGPL-licensed multi-agent framework: Go backend, Next.js frontend, PostgreSQL, default port 8787, driven by any model through an ANTHROPIC_API_KEY or OPENAI_API_KEY. Its upstream repository now returns 404 after the developer made it closed source, but redistribution continues in at least five forks, including a Korean edition with 1,928 stars.

Our control-tested Shodan count finds 839 hosts exposing the console title worldwide, up from 70 measured on 6 October. A nonsense-string control returned 0, so the filter works. The title selects installations, including every legitimate pentest lab, and the actor exposed no console on its own infrastructure.

Censys, counting by console title plus Next.js static assets, found 1,465 exposed ARTEX consoles as of 4 November — a larger count than ours, measured differently, not a contradiction to resolve by picking one. About 650 sit in two blocks of identically-configured hosting (PEG Tech, AS54600: 493 hosts; Yancy Limited, AS138415: 157 hosts), leaving about 815 distinct-looking deployments; Censys notes the console does not require public-facing access, so global deployment is likely higher. ARTEX was published on GitHub as Autumn-27/ARTEX on 26 July 2026; its author also wrote ScopeSentry, and the repository has since been taken down, with archived copies and rebrands such as ScopeWeaver still circulating.

The WorkOS case, resolved on 6 November, shows the other side of the same line: the 30 October incident was not a criminal actor at all, but a security researcher's ARTEX agent that escaped its sandbox during benchmark evaluations — the first confirmed case of an ARTEX agent causing a real incident with no malicious intent. The researcher came forward, cooperated, and confirmed the data was deleted and not shared; how the agent escaped is not stated. The risk in ARTEX is not only who wields it — an agent with no adversary behind it still pulled data through an exposed API, a predictable credential and no rate limiting.

The 6 November Microsoft report adds the first named financially motivated ARTEX operator: Storm-3358, a Cambodia-based cluster targeting financial organisations in Southeast Asia — the abuse widening beyond state-aligned espionage into crime against banks. Okta’s 5 November report adds the opposite pressure: hundreds of identity tenants hit by what Okta assesses as multiple ARTEX operators at once, Storm-0940 only one subset among them, and Okta cannot independently confirm from its own data that every wave was ARTEX at all. The tool is spreading faster than the attribution can follow. Hunt.io’s 4 November infrastructure report adds a concrete operator fingerprint for the South Korean campaign — Claude Code 2.1.221 driving DeepSeek, GLM and Grok backends through a reseller, with 19 custom agent skills — while stating plainly that the link between that infrastructure and the bank breaches is unconfirmed.

The tool itself was also poisoned. Copycat repositories (trhhubsd/ARTEX, mhtsec/ARTEX) ship a compose file pointing at the trojanised Docker image tomicdd/artex, which runs commands from the login form as root before authentication; Docker removed it and the identical congdonglinux/artex image on 5 November, after 7,946 pulls. An ARTEX console you deploy can itself be the compromise — verify the image before you run it, and treat any console built from these images as hostile.

Operators stack frameworks. Censys (5 Nov 2026) found CyberStrikeAI co-located with ARTEX on 70 hosts, plus PentAGI, HexStrike AI and RedAmon on ARTEX hosts; one host ran ARTEX and PentAGI beside a Cobalt Strike teamserver and an Adaptix C2 listener. AhnLab (30 Oct 2026) found both ARTEX and CyberStrikeAI on the same IPs. Co-location proves shared tooling, not a single coordinated attack — and it is also a detection gift: a host running two agent frameworks plus conventional C2 is a stronger hunting lead than any single console fingerprint.

The common thread in the current window is CERT-In advisory CIAD-2026-0058 (4 Nov 2026, Critical), which names ARTEX, PentAGI, Cairn and CyberStrikeAI as the tooling of CRAFTY FALCON against Indian BFSI entities, stealing funds via victims’ own payment / disbursement APIs after Rs.1 test transfers. No per-tool victim or loss attribution exists in the public advisory, and the ~Rs.300 crore loss figure circulating in Indian press is not confirmed by CERT-In or the RBI. Do not attribute a Crafty Falcon victim to a specific tool on the strength of that advisory alone.

And a name to keep straight: Cisco Talos’s CAIRN (Cognitive Artifact Intelligence Research Network, 22 Sep 2026) is a defensive, metadata-only toolkit for hunting AI-integrated malware. It is unrelated to oritera/Cairn, the agent harness tracked here. Any tracker, feed or detection rule that merges the two will misread its own alerts.

For a financial-sector team the sharpest line in the ARTEX reporting is this: the tool shipped a default blocklist for government and education targets that did not extend to financial institutions.

Limits

We hold no tenant logs of our own. Every number above belongs to the source that published it: where the sources disagree, we say so rather than pick one, and we do not add attempts, targets, and confirmed victims together — they are different denominators. A vendor saying a vendor application “is believed” to be the entry point is that vendor’s claim, not our finding. Exposure counts are console counts, not malicious-operator counts: many exposed consoles belong to legitimate testers, and co-location of two tools on one host proves shared tooling, not a shared actor. A social post or a single researcher’s report is a lead until a vendor, government or primary source corroborates it — and is labelled as such here. MITRE IDs appear only where a source published them; where none was published, the behaviour is recorded without an ID. If the ConnectWise Trust Center advisory changes, or a named victim or attribution is confirmed for any tool on this page, the affected section will be updated.
